## Design to do's
- initial thoughts on debugger design, e.g.:
  - what kind of user interface?
    - want something simple that can be evolved into something more sophisticated
    - want to see multiple intermediate values simultaneously, e.g. different graph states?
    - something like a REPL where you can browse into subcomputations
      - (in contrast, say, to a stepping debugger where you jump around the source code)
      - nice idea but "containment" relation misleading because containing variables not always in scope
      - maybe new lexical contexts could be (optionally) shown as such, e.g. in separate window
  - what kind of semantics (e.g. big-step/small-step)
    - related to question about UI, e.g. small-step might suggest a UI where redexes are replaced by reducts
    - can "resugaring" techniques be adapted to big step semantics?
- desugaring
  - language will certainly involve syntactic sugar:
    - existing constructs, e.g. list comprehensions
    - new effects-related constructs, in particular do-notation (but perhaps also assignment, etc)
  - so question will arise of whether "code selections" can be mapped back to surface syntax for intermediate computations
- slicing computations (traces)
  - need a notion of when a computational step is needed
  - e.g. if a step creates a (partial) value, and any part of that value is needed, then that step is needed
  - this notion already exists for pattern-matching: the part of an input matched by a pattern is needed if any part of any output constructed in that dynamic context is needed
  - have used such a notion in the past, but has always been "prefix-closed"; we'll drop that requirement
  - are there situations where we can _elide_ (rather than, say, grey out) unneeded steps?
    - small-step semantics might lend itself better to this
- emulating type classes
  - in languages like Agda and Lean, instances are records and more explicit/first-class
  - naively we could pass instances as explicit arguments, e.g. "do monadState ..."
  - is there a lightweight way of allowing implicit instances?
