\section{Motivating Example}
\label{sec:example}
We present an overview of \OurLang.
Modern climate models such as \todo{cite} consist of a large number of interacting modules.
When a data scientist is investigating a new domain, they often begin by analysing
data in an exploratory fashion. This data may be arranged as a collection of records
like in a relational database. Investigating relationships between these complex
datasets can be difficult.

Let us consider the following example: our hypothetical data scientist is
investigating international water-usage in across nations. Each nation is
represented as a record, with fields for the name of the country,
measures of various water consumption statistics \todo{change this},
alongside their population in millions, and the continent they reside in.

Imagine the users model has produced some charts out of this data. Unfortunately
it's difficult to relate visual elements from one chart to another, or back to
the original dataset. In databases and visualization, this is the common task
of \textit{brushing and linking} \cite{becker87} views of a
dataset. Here, the goal is to connect relevant parts of two structured program
outputs, mediated by their using the same dataset. For example, in \figref{linked-outputs}
we produce both a bar- and bubblechart from the same input dataset. Selecting
a bar on the left highlights the bubbles on the right which are sourced from
the same record. \todo{Need to replace image with a more refined example}

In existing software packages, this is possible but usually done on a bespoke
basis, and may require significant programmer effort. These are not the only
concerns. This functionality usually doesn't come equipped with the ability to
directly inspect the underlying data either, limiting the interpretability of
such structured views.

A related yet distinct task is in interpreting multiple datasets which have had
a relationship induced via some mediating computation. We consider a similar
example to the ones pictured previously. The user has access to some datasets
which co-operate to produce a bubble chart, pictured in \todo{add the figure and ref}.
Here, by placing a selection on one of the input tables, our system - via analysing
the use of data in the output chart - is able to identify the records in the second
dataset that are relevant to the selected records in the first dataset. Aiding
our intepretation is the fact that selection information is also visualized
in the bubblechart.
