\section{Motivating Example}

We present an overview of \OurLang.
Modern climate models such as \todo{cite} consist of a large number of interacting modules.
When a data scientist is investigating a new domain, they often begin by analysing
data in an exploratory fashion. This data may be arranged as a collection of records
like in a relational database. Investigating relationships between these complex
datasets can be difficult.

Let us consider the following example: our hypothetical data scientist is 
investigating water-usage in European countries. Each nation has associated with
it a collection of cities and a measure of the total farmland in that nation.
The user may provide a function for computing the total water consumption of a
nation. We picture this
in \figref{water-query}.

\begin{figure}[h]
\tiny

\caption{Example Water Usage Query}
\label{fig:water-query}
\end{figure}

With the Galois slicing technique, we can follow a selection on the output of
the program - in this case the integer 570 - back in to the inputs of the program.
We use a $\codeSel{yellow box}$ to denote a selection,
when one selection is contained within another, we will use a $\codeSel{\codeSelTwo{green box} inside}$ of
the enclosing yellow box. 
In this case, by selecting the sole (textual) output of the computation, our system discovers the
records - and the appropriate fields - that were used to compute that output.
We picture that in \figref{water-selection}.

\begin{figure}[h]
\tiny
\lstinputlisting[language=Fluid,mathescape]{fig/example/water-selection.fld}
\caption{Showcase of computed backward selection.}
\label{fig:water-selection}
\end{figure}

However, the above is not the interesting to the user. If they have access to the
source code and enough knowledge to interpret that selection, they would maybe
be able to determine this relationship by themself. Let us consider instead the
common the task of \textit{brushing and linking} \cite{becker87} views of a
dataset. Here, the goal is to connect relevant parts of two structured program
outputs, mediated by their using the same dataset. For example, in \figref{linked-outputs}
we produce both a bar- and bubblechart from the same input dataset. Selecting
a bar on the left highlights the bubbles on the right which are sourced from
the same record.

\begin{figure}
\centering
{\includegraphics[scale=0.5]{fig/example/linked-outputs-1.png}}
\caption{Linking of a pair of structured outputs mediated via the same dataset.}
\label{fig:linked-outputs}
\end{figure}

In existing software packages, this is possible but usually done on a bespoke
basis, and may require significant programmer effort. These are not the only
concerns. This functionality usually doesn't come equipped with the ability to
directly inspect the underlying data either, limiting the interpretability of
such structured views.
