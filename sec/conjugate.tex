\subsection{Dependence Graphs}
\label{sec:conjugate:dependence-graphs}
As mentioned earlier in the paper, we make use of dynamic dependence graphs.
%We shall give an account of how we can compute related input and output queries
%efficiently, using dynamic dependence graphs.
Whilst we defer the details of how we arrive at a specific dependence graph
until \secref{core}, we shall introduce the intuition behind them here.


\begin{definition}[Dynamic Dependence Graph]
   A dynamic dependence graph $G = (V,E)$ is a graph where a node $\alpha \in V$
   represents an input to the original program or a value produced during execution,
   and an edge $(\alpha, \alpha') \in E$ exists if, in the evaluation of the program,
   the value associated to $\alpha'$
   \textit{depends} on the value associated to $\alpha$.
\end{definition}

This definition diverges somewhat from traditional approaches to dynamic dependence
graphs since we only consider one type of edge -- a data dependency -- in contrast
to separately defining data and control-flow edges as in \citet{agrawal90}.

In each graph, we mark out a subset of the nodes, $X \subset V$, which represent
the inputs to the program, and a subset of nodes $Y \subset V$, which represent
the outputs. Usually, $X = \sources{G}$, and $Y = \sinks{G}$. Taking the opposite
graph has the effect of swapping the sets of sources and sinks.

In general, a dependency analysis from inputs $X$ to outputs $Y$ can be
characterized by a relation $D \subseteq X \times Y$, where $(x, y) \in D$
can be read as $x$ is \textit{demanded by} $y$.
%
(As opposed to a function) the dependency relation allows scenarios where inputs are not demanded by any
output, or inputs are demanded by multiple outputs. These properties are nice
to have, since in data analysis tasks, we often do not need to make use of all
the inputs to the program, and we may reuse data for multiple different outputs.

Motivated by data analysis tasks, we wish to consider the relationships between sets of inputs and sets of outputs.
Thus, we lift the dependency relation to sets of inputs and sets of outputs by
constructing the \textit{image} and \textit{preimage functions} of the relation:
\begin{definition}[Image and Preimage of a Relation]
   For a relation $D \subseteq X \times Y$, we define $\demandByR_D: \powerset{X} \to \powerset{Y}$
   and $\demandR_D : \powerset{Y} \to \powerset{X}$ as:
   \begin{itemize}
      \item $\demandByR_{D}(X') \eqdef \set{y \in Y \mid \exists x \in X'.(x,y) \in D}$ \hfill (image)
      \item $\demandR_{D}(Y') \eqdef \set{x \in X \mid \exists y \in Y'. (x,y) \in D}$ \hfill (preimage)
   \end{itemize}
\end{definition}
In our setting, we can view the preimage of a set $Y'$ under the dependency relation, $\demandR_{D}(Y')$, as
finding the set of inputs which are necessary for the elements of $Y'$.
Similarly, the image of $X'$ under the dependency relation, $\demandByR_{D}(X')$, can be viewed as the set of outputs that $X'$ is necessary
for.
%
Accordingly, in the rest of the paper,
when we refer to \textit{demands}, we mean $\demandR_{D}(\param)$,
and when referring to \textit{demanded by}, we mean $\demandByR_{D}(\param)$.
We shall make use of the fact that the image of $X'$ under a relation
is equal to the preimage of $X'$ under the inverse relation $D^{-1}$,
ie $\demandByR_{D}(X') = \demandR_{D^{-1}}(X')$.

A related question we may come across in data analysis tasks is that of \textit{sufficiency}. For the values in $X'$ to be sufficient for some output, $y \in Y$, we need
$x_i \in X'$ for every $(x_i, y) \in D$.
As a simple example, consider the expression $3 + 4$, neither
of the subexpressions $3$ or $4$ are sufficient to produce the result of
evaluating the expression on their own. We make the observation that
the set of outputs that a set of inputs is necessary for is a superset of the
outputs it is sufficient for.

We note that these two functions do not always form a Galois connection, since
the composition of the two functions is not necessarily monotonic, contradicting
a basic fact of Galois connections, which we picture in \figref{relation-not-galois}.
In \figref{relation-not-galois-1}, we apply $\demandByR_D$ to $\set{x_1, x_2}$, and find
$\set{y_1, y_2}$. We then apply $\demandR$ to $\set{y_1, y_2}$, and get $\set{x_2, x_3}$, which is
neither a superset, nor a subset of the originally selected set. Since the composite function
$\demandR_D \after \demandByR_D$ is neither increasing or decreasing, the functions
cannot form a Galois connection. We picture the same scenario reversed in \figref{relation-not-galois-2}.
We can read the green set as unused inputs, or free outputs. The light blue sets are the
elements we have "discovered" via applying the two functions one after another.
We can think of the darker blue sets as the values about which we discover nothing new
when applying the two functions.

Instead of a Galois connection, we shall instead see that these two functions are
\textit{conjugate}, in the sense of \citet{jonsson51}:

\begin{definition}[Conjugate Functions]
   For Boolean algebras, $\powerset{X}$, and $\powerset{Y}$, functions $f: \powerset{X} \to \powerset{Y}$
   and $g: \powerset{Y} \to \powerset{X}$, and subsets $X' \subseteq X$ and $Y' \subseteq Y$,
   we say that $f, g$ form a \textit{conjugate pair}
   if the following holds:
   $$
   f(X') \cap Y' = \emptyset \iff X' \cap g(Y') = \emptyset
   $$
   Or equivalently:
   $$
   f(X') \cap Y' \neq \emptyset \iff X' \cap g(Y') \neq \emptyset
   $$
\end{definition}

This makes sense as a condition for \textit{demands} and
\textit{demanded by}: if for some subsets $X',Y'$, we find that the output values
$X'$ is demanded by has an empty intersection with $Y'$, we would expect the set
of input values that $Y'$ demands to have an empty intersection with $X'$.

\begin{lemma}[Preimage and Image of a relation are conjugate]\label{lem:im-preim}
   For a relation $D \subseteq X \times Y$, and subsets $X' \subseteq X, Y' \subseteq Y$,
   $\demandByR_{D}(\param)$ and $\demandR_{D}(\param)$ are conjugate.
\end{lemma}

We observe that if we restrict the set of inputs $X$ and outputs $Y$ in the graph such that there are
no inputs which are unused, then $\demandR$ will preserve $\bot$, ie $\demandR(\emptyset) = \emptyset$.
This means that applying $\demandByR$ after $\demandR$, we will not lose any of
the originally selected inputs.
\begin{lemma}
   If $\demandByR_D(\emptyset) = \emptyset$, then $\demandR \after \demandByR$ is
   increasing.
\end{lemma}
Similarly, if we have no outputs which are free, then $\demandByR$ will also
preserve $\bot$, and composing the functions in the opposite way will also
be increasing.
\begin{lemma}
   If $\demandR_D(\emptyset) = \emptyset$, then $\demandByR \after \demandR$ is
   increasing.
\end{lemma}
As a corollary, if both of the above lemmas are true, then $\demandR$ and $\demandByR$ actually
do form a(n antitone) Galois connection. This is useful to know, since we may be
working in a context where we wish to consider a filtered view of the data, where
the user is shown only the data used by the original program. \cd{does this become relevant in any of the benchmarks?}

to be used, and each input can only be used once. If that
is the case, then taking the image and preimage of the function doesn't just create
a conjugate pair, but instead creates the usual image/preimage Galois connection for

\subsection{Computing Demands and Demanded By over Dependence Graphs}
\label{sec:conjugate:dependence-graph-algos}
We now provide some detail on the computation of
\textit{demands} and \textit{demanded by} on a concrete dependence graph.
Whilst one can view a graph abstractly as a collection of vertices and edges, we
will define it  as a finite map of pairs $(v : U)$ denoting that a vertex $v$ has
outgoing edges to all vertices in $U \subseteq V$.
\begin{definition}[In and Out Edges]
   For a graph $G=(V,E)$, and a node $\alpha \in V$, we define:
   \begin{itemize}
      \item $\inE{G}(\alpha) \eqdef \set{(\beta, \alpha) \mid (\beta, \alpha) \in E}$\hfill (in edges)
      \item $\outE{G}(\alpha) \eqdef \set{(\alpha, \beta) \mid (\alpha, \beta) \in E}$\hfill (out edges)
   \end{itemize}
\end{definition}
\begin{definition}[Graphs as finite maps]
   A graph $G =(V,E)$ is a finite map $G_M \eqdef \set{\seq{\bind{v}{U}}}$,
   where $\bind{v}{U} \in G_M \iff v \in V$, $U \subseteq V$ and $(v, u_i) \in E$ for all $u_i \in U$
\end{definition}
When constructing a graph incrementally, we may exploit this notation, and use
$\bind{v}{U}$ to refer to a "star" graph, with one central node pointing at its
neighbours.
We will often refer to a graph without explicitly referring to its representation
as a map, or a pair of sets.
Once a graph has been constructed, the set of nodes that a value is demanded by
can be represented by the set of nodes which are reachable by traversing the
edges of the graph, where we use the standard understanding of the reachability relation $R_G$ for  $G=(V,E)$ as the reflexive transitive
   closure of $E$.

\begin{definition}[Related Inputs and Outputs]
   For $G = (V,E)$, define:
   \begin{enumerate}
      \item $\relInput_{G} \eqdef \demandByR_{G} \after \demandR_{G}$\hfill (related inputs)
      \item $\relOutput_{G} \eqdef \demandR_{G} \after \demandByR_{G}$\hfill (related outputs)
   \end{enumerate}
\end{definition}
A related input query can now be phrased as "what else can reach the nodes I can
reach in the graph?", and a related output query can be phrased as "what else can
be reached by the things that reach me?". We can think of this notion as similar
to that of "cognacy" in natural languages, for related outputs we are finding
the common ancestors, and for related inputs the common descendants.

To calculate a related input query, the first step is to select
the input of interest, $X' \subseteq \sources{G}$. We proceed by finding all nodes
in the output that our selected input nodes are demanded by, $\demandByR(X')$.

We compute this set by the algorithm $\demandsAlg{}$ detailed in \figref{conjugate:algorithms:demands}.
The algorithm computes reachability by incrementally building a subgraph $G'$,
consisting of all nodes and edges that can be traversed from the initial starting set.
$\demandsAlg{}$ begins by taking a set of nodes and accumulating their neighbours.
Every time a new node is reached by traversing an edge, we enqueue its own
neighbours, and add it to the graph we are constructing (\ruleName{$\demandsVert{}$-extend}).
If we traverse an edge and reach a node we've already met, we simply skip it
(\ruleName{$\demandsVert{}$-skip})
At the algorithms termination (\ruleName{$\demandsVert{}$-done}), we have traversed every
edge and node reachable from the input set.
Once it has terminated, and we have constructed the subgraph of demanded nodes,
we filter out any nodes which do not appear as outputs by only considering the
graphs set of sinks, $\sinks{G'}$ (\ruleName{$\demandsAlg{}$}).

\begin{proposition}[Reaches Computes Demanded By]
   For a graph $G = (V,E)$, a subset of inputs $X' \subseteq \sources{G} \subset V$
   the following holds:
   $$
    \forall G' .\  X' \demandsAlg{G} \sinks{G'} \iff \demandByR_G(X') = \sinks{G'}

\begin{proposition}[Correspondence Between Conjugates and Galois Connections]
   Let $A,B$ be Boolean algebras, $f: A \to B$ and $g: B \to A$.
   The following statements are equivalent:
   \begin{itemize}
      \item $f$ and $g$ form a conjugate pair
      \item $f$ and $\dual{g}$ form a Galois connection
   \end{itemize}
\end{proposition}

\begin{lemma}[Sufficiency is the dual of necessity]
   For a graph $G = (V,E)$ with inputs $X \subseteq V$ and a subset of the inputs $X' \subseteq X$
   the following holds:
   $$\dual{\demandByR_G(X')} = \sufficientR_G(X')$$
\end{lemma}

Because of the lemma above, we could reuse $\demandsAlg{}$ in order to compute
this, by taking the complements of the input sets, running $\demandsAlg{}$, and
then complementing the output, however this could in practise be inefficient,
since taking complements of large sets can be an expensive operation. We therefore
provide a more efficient implementation of the sufficiency analyis, detailed in
\figref{conjugate:slicing:forward}.

The algorithm $\fwdAlg{G}$ builds a subgraph of the original dependence graph,
similar to $\demandsAlg{}$. In the main subroutine, $\fwdEdges{}$, we consider
the subgraph under construction $G$, the subgraph of pending nodes $H$, and
the current set of edges under consideration $E$. For efficiency, the algorithm
proceeds in a manner which allows it to only traverse each edge in the graph once.
When considering an edge $(\alpha, \beta)$ in the edge list, $E$, we proceed by
adding it to $H$.
If doing so causes the neighbours of $\alpha$ in $H$ to be equal
to its neighbours in $G_0$ (the base dependency graph), then we can remove $\alpha$ from $H$, and add it
to $G$ (\ruleName{$\fwdEdges{}$-extend}), before adding its outgoing edges to $E$.

Because the edges in the parent graph $G$ all point in the direction of inputs to
outputs, computing the inward neighbours of a node is inefficient in the adjacency
map. We therefore perform the check related to input neighbors of a node on the
opposite adjacency map.

Otherwise, we extend the edges in $H$ with $(\alpha, \beta)$, and proceed (\ruleName{$\fwdEdges{}$-pending}).
The algorithm terminates when there are no more edges to be considered (\ruleName{$\fwdEdges{}$-pending}).
When this happens, it is possible that $H$ is non-empty. This implies that during
the algorithms execution, we have traversed at least one node without traversing
all of its in-edges. Thus, $H$ forms a sort of front of nodes for which the
input nodes only provide partial information.
