\section{Conjugate Operators For Dynamic Dependence Graphs}
\label{sec:conjugate}

We shall introduce some preliminary notions, before building up the intuition
needed to formally define \textit{demands} and \textit{demanded by}. Then, we shall
explain how we can refine queries on input-output relationships. Finally, we will describe the
connection to the state-of-the-art in this area.

\subsection{Background notions and notation}
For a relation $D \subseteq X \times Y$, we write $D^{-1} \subseteq Y \times X$ to
denote the inverse relation, where $(y,x) \in D^{-1} \iff (x,y) \in D$. 

For a set $X$, we write $\compl{X}$ to denote it's complement.
For two sets, $A, B$, we write $A \setminus B \eqdef A \wedge \compl{B}$ for the relative complement
of $B$ within $A$. 
\newline
We use the standard notion of Boolean algebra as a lattice $(X, \leq)$, where the operations of meet ($\wedge$)
and join ($\vee$) distribute over each other, and for each element $x \in X$,
there is a complement element $\compl{x} \in X$.
%
For the rest of this section, when we refer to Boolean algebras, we usually mean
the powerset lattice $\powerset{X}$, where the elements are subsets $X' \subseteq X$,
the order is set inclusion $\subseteq$, and meet and join are given by intersection ($\cap$)
and union ($\cup$), respectively.

For a graph $G = (V,E)$, we write $G^{-1} \eqdef (V,E^{-1})$ for the opposite graph,
where $\param^{-1}$ denotes the inverse of an edge. Also, we write $\sources{G}$ for
the source vertices in a graph, and $\sinks{G}$ for the sinks.

\subsection{Dependence Graphs}
We shall give an account of how we can compute related input and output queries
efficiently, using dynamic dependence graphs.

\begin{definition}[Dynamic Dependence Graph]
   A dynamic dependence graph $G = (V,E)$ is a graph where the nodes $\alpha \in V$
   represent values in the original program, and an edge $(\alpha, \alpha') \in E$
   exists if in the evaluation of the program, the value associated to $\alpha$
   \textit{depends} on the value associated with $\alpha'$
\end{definition}

We shall not consider the details of how we arrive at a specific dependence graph
until we reach \secref{core}. For now, it is enough to note that a dependence
graph is computed as part of program evaluation, with the nodes associated to
any value in the original program, or values which arise during execution.

This definition diverges somewhat from traditional approaches to dynamic dependence
graphs since we only consider one type of edge -- a data dependency -- in contrast
to separately defining data and control-flow edges as in \citet{agrawal90}.

In each graph, we mark out a subset of the nodes, $X \subset V$ which represent
the inputs to the program, and a subset of nodes $Y \subset V$ which represent
the outputs. Usually, $X = \sources{G}$, and $Y = \sinks{G}$. In the opposite graph,
this is flipped.

Before we give the definitions of \textit{demands} and \textit{demanded by}, we
shall provide some more intuition on our setting, and how it leads us to the
conditions we need.

In general, a dependency analysis from inputs $X$ to outputs $Y$ can be
characterized by a relation $D \subseteq X \times Y$, where $(x, y) \in D$
can be read as $x$ is \textit{demanded by} $y$.

Let us first consider the case when the relation is a function $f: X \to Y$.
If, for some input $x \in X$, we find that $f(x) = y$, for some $y \in Y$, we
can say that $x$ is demanded by $y$, or that $x$ is sufficient to produce $y$.

We do not, in general, wish to consider individual input or output values on their
own. Instead, we like to consider sets of inputs, and sets of outputs. Thus we
must lift the function to sets.
It is well known that we can lift this function to the image and preimage functions of $f$:
\begin{definition}[Image and Preimage of a Function]
   For a function $f: X \to Y$ and $X' \subseteq X$, $Y' \subseteq Y$ define:
   \begin{itemize}
      \item $f^{\star}(X') \eqdef \set{f(x) \mid x \in X'}$ \hfill (image)
      \item $f_{\star}(Y') \eqdef \set{x \in X \mid \exists y \in Y' . f(x) = y}$ \hfill (preimage)
   \end{itemize}
\end{definition}
The above pair of functions forms the usual image/preimage Galois connection for a function.
\cd{I would probably not phrase this is a lemma (i.e. lemma 3.2), but leave it as an obvious remark -- is that a stretch? This way we avoid needing a proof.}
\begin{lemma}[Galois Connection]
   $f^{\star}(X') \subseteq Y' \iff X' \subseteq f_{\star}(Y')$
\end{lemma}
In this setting, it is possible to read the action of $f^{\star}$ on a set $X'$
as telling us which outputs $X'$ is sufficient for, since it tells us every output
we can make with any element of $X'$, but also what the values of $x$ are necessary for.
Similarly, we can read the action of $f_{\star}$
on a set $Y'$ as telling us which inputs are necessary to make any element of $Y'$.

Whilst the above is attractive, this is not the generalization to sets of values
that we want.  Firstly, since $D$ is a function, it requires that every input
value is used by a program. In the realm of data analysis, this is
not always true. We may take a very large table as our input, and only consider
a subset of the columns. Secondly, by restricting ourselves to functions, we force
each input value to be used by only a single output value in a program. If the same
input value is used in multiple ways, we would need to provide multiple copies
of each input value.

Thus, we cannot begin with functions from $X \to Y$, and consider the more general
dependency relations instead. With a dependency relation, not every input needs to
have an output which demands it, and an input may be used by multiple outputs.
Thus, to generalize dependency to sets of inputs and sets of outputs, we can lift
the relation to its image and preimage:
\begin{definition}[Image and Preimage of a Relation]
   For a relation $D \subseteq X \times Y$, we define:
   \begin{itemize}
      \item $D_{\demandByR}(X') \eqdef \set{y \in Y \mid \exists x \in X'.(x,y) \in D}$ \hfill (image)
      \item $D_{\demandR}(Y') \eqdef \set{x \in X \mid \exists y \in Y'. (x,y) \in D}$ \hfill (preimage)
   \end{itemize}
\end{definition}
In this setting, whilst we can still view the preimage $D_{\demandR}(Y')$ as
finding the set of inputs which are necessary for the elements of $Y'$, we can
no longer view $D_{\demandByR}(X')$ as the set of outputs that $X'$ is sufficient
for. This is because sufficiency means having all of the inputs required to
produce an output. As a simple example, consider the expression $3 + 4$, neither
of the subexpressions $3$ or $4$ are sufficient to produce the result of
evaluating the expression on their own. The image instead gives us the set of
outputs that $X'$ is necessary for. We make the observation that
the set of outputs that a set of inputs is necessary for is a superset of the
outputs it is sufficient for.


We shall make use of the fact that the image of $X'$ under a relation
is equal to the preimage of $X'$ under the inverse relation $D^{-1}$, 
ie $D_{\demandByR}(X') = D^{-1}_{\demandR}(X')$.


We note that in general, these two operators do not form a Galois connection, since
the composition of the two functions is not monotonic, see \figref{relation-not-galois}

Instead of a Galois connection, we shall instead see that these two functions are
\textit{conjugate}, in the sense of \citet{jonsson51}:

\begin{definition}[Conjugate Functions]
   For Boolean algebras, $\powerset{X}$, and $\powerset{Y}$, functions $f_{\demandR}: \powerset{X} \to \powerset{Y}$
   and $f_{\demandByR}: \powerset{Y} \to \powerset{X}$, and subsets $X' \subseteq X$ and $Y' \subseteq Y$,
   we say that $(f_{\demandR}, f_{\demandByR}): \powerset{X} \to \powerset{Y}$ are a \textit{conjugate pair}
   if the following holds:
   $$
   f_{\demandR}(X') \cap Y' = \emptyset \iff X' \cap f_{\demandByR}(Y') = \emptyset
   $$
   Or equivalently:
   $$
   f_{\demandR}(X') \cap Y' \neq \emptyset \iff X' \cap f_{\demandByR}(Y') \neq \emptyset
   $$
\end{definition}

This makes sense as a condition for \textit{demands} and
\textit{demanded by}: if for some subsets $X',Y'$, we find that the resources
$X'$ is demanded by has an empty intersection with $Y'$, we would expect the set
of resources that $Y'$ demands to have an empty intersection with $X'$.

We use the following notation to give the functions for \textit{demands} and
\textit{demanded by} for a relation:
\begin{definition}[Demands and Demanded by for a dependency relation]
   For a relation $D \subseteq X \times Y$, define:
   \begin{itemize}
      \item $\demandR_D(X) = D[X]$ \hfill (demands)
      \item $\demandByR_D(Y) = \preim{D}[Y]$ \hfill (demanded by)
   \end{itemize}
\end{definition}
By treating \textit{demands} and \textit{demanded by} as the image
and preimage functions of a dependency relation $D$, we get their
conjugacy for free.

\subsection{Computing Demands and Demanded By over Dependence Graphs}
\label{conjugate:dependence-graph-algos}
We now provide some detail on the computation of
\textit{demands} and \textit{demanded by} on a concrete dependence graph.
We shall also introduce some more notation, used to read the definitions of the
algorithms in \figref{conjugate:reaches}.

\begin{definition}[Finite Sequences]\label{def:list}
   Write ${\seq{a}}$ to denote a finite sequence of elements $\seqRange{a_1}{a_n}$.
\end{definition}

\begin{definition}[Cons/snoc of finite sequences]\label{def:cons}
   For finite sequence $\seq{a}$ and element $a$, write $a \cons \seq{a}$ for
   cons (prepending $a$ to $\seq{a}$)  and $\seq{a} \cons a$ for snoc (appending $a$ to $\seq{a}$).
\end{definition}

\begin{definition}[Finite Maps]\label{def:finite-map}
   Write $\set{\seq{\bind{k}{a}}}$ to denote a set of pairs $\seqRange{\bind{k_1}{a_1}}{\bind{k_n}{a_n}}$
   where keys $\seqRange{k_1}{k_n}$ are pairwise unique.
\end{definition}

Whilst we can view a graph abstractly as a collection of vertices and edges, it
will be concretely represented as a finite map.
\begin{definition}[Graphs as Finite Maps]
   A graph $G =(V,E)$ can be viewed as a finite map $M \eqdef \set{\seq{\bind{v}{\seq{a}}}}$,
   where a pair $\bind{v}{\seq{a}} \in M \iff v \in V$ and $(v, a_i) \in E$ for all $a_i \in \seq{a}$
\end{definition}

\begin{definition}[Disjoint union of finite maps]\label{def:disjoint-union}
   For finite maps $M$, $M'$ with $\dom{M} \cap \dom{M'} = \emptyset$, define $M \disjunion M' = M \cup M'$.
\end{definition}

We also use the $\cons$ notation in \defref{cons} for sets and finite maps in the following way:

\begin{definition}[Set insertion]
   For set $A$ and element $a$,  write $a \cdot A$ or $A \cdot a$ to mean $A \disjunion \set{a}$.
\end{definition}
\begin{definition}[Map extension]
   For finite map $M$ and pair $(k : a)$,  write $(k : a) \cdot M$ or $M \cdot (k : a)$ to mean $M \disjunion \set{(k : a)}$.
\end{definition}

Once a graph has been constructed, we must look at which nodes can be reached from
other nodes by traversing edges in the graph.
\begin{definition}[Reachability]
   For a graph $G=(V,E)$, the \textit{reachability relation} $R_G$ is the \textit{reflexive transitive
   closure} of $E$.
\end{definition}

When we are considering a graph $G$ and its opposite $G^{-1}$,
we will abuse the notation for the preimage and image of $R$,
since $R_G^{-1} = R_{G^{-1}}$. We can now define \textit{demands}
and \textit{demanded by} in terms of $R$.

\begin{definition}[Demands and Demanded By on a Graph]
   For a graph $G = (V,E)$ with reachability relation $R_G \subseteq V \times V$, we write

   \begin{itemize}
      \item $\demandR_G$(X) \eqdef $\demandR_{R_G} (X)$ \hfill (demands)
      \item $\demandByR_G$(Y) \eqdef $\demandByR_{R_G} (Y)$ \hfill (demanded by)
   \end{itemize}
\end{definition}

Defining these two functions on the reachability relation now lets us give
a formal account of related inputs and related outputs queries.
\begin{definition}[Related Inputs and Outputs]
   For $G = (V,E)$, define:
   \begin{enumerate}
      \item $\relInput_{R_G} \eqdef \demandR_{R_G} \after \demandByR_{R_G}$\hfill (related inputs)
      \item $\relOutput_{R_G} \eqdef \demandByR_{R_G} \after \demandR_{R_G}$\hfill (related outputs)
   \end{enumerate}
\end{definition}
A related input query can now be phrased as "what else can reach the nodes I can
reach in the graph?", and a related output query can be phrased as "what else can
be reached by the things that reach me?". We can think of this notion as similar
to that of "cognacy" in natural languages, for related outputs we are finding
the common ancestors.

To calculate a related input query, the first step is to select
the input of interest, $X' \subseteq \sinks{G}$. We proceed by finding all nodes
in the output that our selected input nodes are demanded by, $\demandByR(X')$.

We calculate this set by the algorithm detailed in \figref{conjugate:reaches}.

Since $\demandByR(X) \subseteq \sources{G}$, we can take the result and apply
$\demandR(\param)$. We can compute this be reusing \textit{reaches} on the
opposite graph.

The procedure for computing related outputs is similar, we simply swap the order
of operations.
\input{fig/conjugate/reaches}

The procedure detailed in \figref{conjugate:reaches} works by
traversing the neighbors of the selected set of nodes, until no new neighbors
can be found. The procedure builds a graph, $G'$, which is a subgraph of $G$
corresponding to the subset of nodes in $G$ which are reachable from the input
set. When it finishes running, we take $\sinks{G'}$ to be the set of outputs
related to the initially selected inputs.
\begin{proposition}[Reaches Computes Demands]
   For a graph $G = (V,E)$ and a subset of the outputs $Y \subseteq \sources{G} \subset V$
   The following holds:
   $$
      Y \reachesAlg{G} \sinks{G'} \iff \demandR_G(Y) = \sinks{G'}
   $$
\end{proposition}

\subsection{Relationship to Galois Slicing}
We mentioned earlier that $\demandByR(X')$ can be read as asking "What is $X'$
necessary for?" Asking this question naturally leads us to ask how we can
adapt this analyis to answer the question "what is $X'$ \textit{sufficient} for?"

\begin{definition}[Sufficiency]
   For a graph $G=(V,E)$ with reachability relation $R_G \subseteq V \times V$,
   inputs $X \subseteq V$, outputs $Y \subseteq V$ we define:
   \begin{itemize}
      \item $\sufficientR_G(X') \eqdef \set{y \in Y \mid \demandR_G (y) \subseteq X' }$ \hfill (sufficiency)
   \end{itemize}
\end{definition}
It turns out that we can modify $\demandByR(\param)$ into this query on
sufficiency, using the De Morgan Dual.

\begin{definition}[De Morgan Dual]
   For Boolean algebras $A, B$, and a function $f: A \to B$, we define the
   \textit{De Morgan Dual} $\dual{f}: A \to B$ of $f$ as:
   $$
   \dual{f} \eqdef \neg_B \after f \after \neg_A
   $$
\end{definition}

\begin{proposition}[Correspondence Between Conjugates and Galois Connections]
   Let $A,B$ be Boolean algebras, $f: A \to B$ and $g: B \to A$. Define:
   $$
      h \eqdef \dual{g}
   $$
   Then the following statements are equivalent:
   \begin{itemize}
      \item $f$ and $g$ form a conjugate pair
      \item $f$ and $h$ form a Galois connection
   \end{itemize}
\end{proposition}

\begin{lemma}[Sufficiency is the dual of necessity]
   For a graph $G = (V,E)$ with inputs $X \subseteq V$ of the inputs $X \subseteq X$
   the following holds:
   $$\dual{\demandByR_G(X')} = \sufficientR_G(X')$$ 
\end{lemma}

Because of the lemma above, we could reuse \textit{reaches} in order to compute
this, by taking the complements of the input sets, running \textit{reaches}, and
then complementing the output, however this could in practise be inefficient,
since taking complements of large sets can be an expensive operation. We therefore
provide a more efficient implementation of the sufficiency analyis, detailed in
\figref{conjugate:slicing:forward}.

\begin{proposition}[Forwards Computes Sufficency]
   For a dependence graph $G= (V,E)$, and a subset of the inputs $X' \subset V$
   the following holds:
   $$
       X' \fwdAlg{G} \sources{G'} \iff \sufficientR(X') = \sources{G'}
   $$
\end{proposition}

It turns out that the Galois connection created with \textit{sufficiency} and
\textit{demands} exactly mirrors a Galois connection used in the current state
of the art for linked visualization work, \citet{perera22}. In that work, the
authors use this Galois connection to perform program slicing, by constructing
an execution trace of a program, which is used to propagate selection information
between inputs and outputs. Their work relies on rewinding and replaying this
execution trace with different selection states, meaning it takes time proportional
to the execution of the original program. In contrast, running slicing queries
over a graph is efficient, only taking time proportional to the portion of the
graph that's actually traversed.
