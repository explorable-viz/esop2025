\section{Conjugate Operators For Dynamic Dependence Analysis}
\label{sec:conjugate}

We shall introduce some preliminary notions, before building up the intuition
needed to formally define \textit{demands} and \textit{demanded by}. Then we shall
explain how we can refine queries on input-output relationships, as well as
a connection to the state of the art in this area.
\subsection{Notation}
For a set $X$, we write $\compl{X}$ to denote it's complement within a larger set.
For a relation $D \subseteq Y \times X$, and a subset $Y' \subseteq Y$, we write
$D[Y']: \powerset{Y} \to \powerset{X}$ for the image of $Y'$ under $D$. For a
subsert $X'\subseteq X$ we similarly write $\preim{D}[X']: \powerset{X} \to \powerset{Y}$
for the preimage of $X'$ under $D$.

For the rest of this section, when we refer to Boolean algebras, we usually mean
the powerset lattice. Therefore we use the set theoretic symbols $\cap$ and
$\cup$ for meet and join.

Notationally we make use of the fact that the image of $Y'$ under a relation
$D$ is equal to the preimage of $Y'$ under the inverse relation $D^{-1}$.

For a graph $G = (V,E)$, we write $G^{-1} \eqdef (V,E^{-1})$ for the opposite graph,
where $\param^{-1}$ denotes the inverse of an edge. We write $\sources{G}$ for
the source vertices in a graph, and $\sinks{G}$ for the sinks.
\subsection{Preliminaries}

Before we give the definitions of \textit{demands} and \textit{demanded by}, we
shall illuminate the intuitive properties we would expect them to have. We would
expect the two functions to possess some notion of symmetry. If some inputs
are demanded by some outputs, then of course we expect those outputs to demand
those inputs. 

In light of this, we might expect the functions used to determine \textit{demands}
and \textit{demanded by} to be inverses of each other. It turns out this notion
is not quite correct. We do not consider individual values in the set of inputs
or outputs, and when selecting a set of inputs, we may select an input that is
entirely unused by the program.
If we were to insist our operations were inverse, it would imply that for a set of
inputs to be demanded by a set of outputs, every input in the set should be used,
which is clearly not always the case. We instead relax the requirement from the
two operations being inverse to their being, \textit{conjugate}, in the sense of \citet{jonsson51}:

\begin{definition}[Conjugate Functions]
   For Boolean algebras, $\powerset{X}$, and $\powerset{Y}$, functions $f: \powerset{X} \to \powerset{Y}$
   and $g: \powerset{Y} \to \powerset{X}$, and subsets $X' \subseteq X$ and $Y' \subseteq Y$,
   we say that $f$ and $g$ are \textit{conjugate} if the following holds:
   $$
      f(X') \cap Y' = \bot \iff X' \cap g(Y') = \bot 
   $$
   Or equivalently:
   $$
      f(X') \cap Y' \neq \bot \iff X' \cap g(Y') \neq \bot
   $$
\end{definition}

Straightforwardly, we would expect this condition to hold for \textit{demands} and
\textit{demanded by}: if for some subsets $X',Y'$, we find that the resources
$X'$ is demanded by has an empty intersection with $Y'$, you would expect that
the resources $Y$ demands has an empty intersection with $X'$.n Whilst the property
itself is simple, it has useful consequences.


Firstly, we would expect \textit{demands} and \textit{demanded by} to be monotonic
in their inputs: taking a selection on the output and growing it (selecting more)
should cause the size of the demand to stay the same, or grow.
We similarly expect the same property of \textit{demanded by}.  It turns out that
Conjugate functions are not only monotonic, but join-preserving: $f(X \cup Y) = f(X) \cup f(Y)$.
From the perspective of resource demand, this makes sense: if we are investigating
what two resources demand in totality, we do not expect them to demand a resource
that neither of them demanded individually. 

The fact that we may have unused inputs, or outputs not present as variables means
that despite this, we cannot necessarily expect these functions to preserve the
whole input set. If there are inputs that are unused, then running demands on
the whole output will necessarily miss out all the unused inputs. Later, we shall
see how we can overcome this limitation, and use this to discover more information
about the relationship between inputs and outputs.

   then $\funProd{f}{g}$ and $\funProd{f'}{g'}$ form a conjugate pair.
\end{lemma}

Lastly, we need to define the De Morgan Dual of a function, since it becomes useful
when connecting our work to the state of the art of this area.
\begin{definition}[De Morgan Dual]
   For Boolean algebras $A, B$, and a function $f: A \to B$, we call the function
   $\dual{f}: A \to B$ the \textit{De Morgan Dual} of $f$, and define it as: 
   $$
   \dual{f} = \neg_B \after f \after \neg_A
   $$
\end{definition}

We shall now consider how we can use the notions above, as well as properties
of graphs to give an account of the efficient computation of related inputs
and outputs. 


For the rest of this section, all graphs we consider will be constructed during
program evaluation. 

\begin{definition}[Dynamic Dependence Graph]
   A dynamic dependence graph $G = (V,E)$ is a graph where the nodes $\alpha \in V$
   represent values in the original program, and an edge $(\alpha, \alpha') \in E$
   exists if, in the original program, the value associated to $\alpha$
   \textit{depends} on the value associated with $\alpha'$
\end{definition}where the nodes represent values

The choice of dependency relation used to construct such a graph is irrelevant
at this stage, we shall return to this discussion point in \secref{core}. Our
work diverges from traditional approaches to dynamic dependence graphs since we
only consider one type of edge, in contrast to separately defining data and
control-flow edges as in \citet{agrawal90}.

When a dependence graph $G$ is constructed, the sources $\sources{G}$ correspond
to the output nodes, and the sinks $\sinks{G}$ correspond to input nodes. In the
opposite graph, this correspondence is flipped.  

\begin{definition}[Reachability]
   For a graph $G=(V,E)$, the \textit{reachability relation} $R_G$ is the \textit{reflexive transitive
   closure} of $E$.
\end{definition}

In some cases, a value in a program will be directly copied from the input to the
output. In these cases, no edge will be constructed in the dependence graph. To
avoid the problems this could cause, we extend the reachability relation
with pairs of the form $(\alpha, \alpha)$. We can read this as the value
depending on itself. 

For the rest of this section we generally omit the $\param_G$
from this relation, since it is usually obvious to which graph we refer.
When we are considering a graph $G$ and it's opposite $G^{-1}$,
we will abuse the notation for the preimage and image of $R$,
since $R_G^{-1} = R_{G^{-1}}$. We can now define \textit{demands}
and \textit{demanded by} in terms of $R$.

\begin{definition}[Demands and Demanded By]
   For a graph $G = (V,E)$ with inputs $X \subseteq \sinks{G} \subset V$ and outputs
   $Y \subseteq \sources{G} \subseteq V$, with reachability relation $R_G$,
   and define them by the following:
   \begin{itemize}
      \item $\demandR_G \eqdef \restrict{R_G}{S(G) \times T(G)}[\param]$ \hfill (related outputs)
      \item $\demandByR_G = \demandR_{G^{-1}}$ \hfill (related inputs)
   \end{itemize}
\end{definition}

One feature of our work runs parallel to a line of research due to \citet{perera22}.
In that work, the authors devise a method for computing related output queries,
using program slicing operators which form a \textit{Galois connection}. It is not
surprising that we can recover their frameworks capabilities from ours, due to
a well known fact about conjugate functions:

\begin{proposition}[Correspondence Between Conjugates and Galois Connections]
   Let $A,B$ be Boolean algebras, $f: A \to B$ and $g: B \to A$. Define $h \eqdef \dual{g}$.
   Then the following statements are equivalent:
   \begin{itemize}
      \item $f$ and $g$ form a conjugate pair
      \item $f$ and $h$ form a Galois connection
   \end{itemize}
\end{proposition}

The Galois connection we use is defined in the following way:

\begin{definition}[Galois Connection For A Relation]
   For a relation $D \subseteq Y \times X$, we write $D_{\star} \dashv D^{\star} : \powerset{X} \to \powerset{Y}$
   to mean the image/preimage Galois connection for a function $f : X \to Y$, with the direction of the relation
   flipped, and the functions defined as:
   \begin{itemize}
      \item $D_{\star}(Y') \eqdef D[Y']$
      \item $D^{\star}(X') \eqdef \dual{(\preim{D}[X'])}$
   \end{itemize}
\end{definition}

We can then recover their data-linked visualizations by treating the output views
as a product of two individual views. The notion of conjugate functions is closed
under the Cartesian product, and so we can take the product of two output views,
and still recover a Galois connection between the inputs and the outputs, allowing
us to reconstruct their linked visualizations. Despite this our approach does differ
somewhat. In their paper, the authors construct multiple separate Galois connections,
between the inputs and each of the pairs of outputs. In contrast, taking the product
view, we can construct a single graph which contains both, and then restrict our
attention to nodes which appear in only one or the other.
