\section{Conjugate Operators For Program Slicing}
\label{sec:conjugate}

In this section, we shall introduce some mathematical notions, explain why they
are useful to us, and then use them to define the operations we use to compute
related inputs and related outputs queries.

\subsection{Preliminaries}

\begin{definition}[Complement]
   For any set $X$ and any $Y \subseteq X$, write $\compl{Y} \subseteq X$ to denote the \textit{complement}
   of $Y$ with respect to $X$.
\end{definition}

\begin{definition}[Image and Preimage]
   For a relation $D \subseteq Y \times X$, and a subset $Y' \subset Y$, we write
   $D[Y'] : \powerset{Y} \to \powerset{X}$ to denote the image of $Y'$ under $D$. For a subset $X' \subseteq X$
   we write $\preim{D}[X'] : \powerset{X} \to \powerset{Y}$ to denote the preimage of $X'$ under $D$.
\end{definition}

We swap the usual order of $X$ and $Y$, since it allows us to read $Y \mathrel{D} X$ as
"outputs $Y$ demand inputs $X$".

For the this section, when we refer to Boolean algebras, we are
usually referring to the powerset lattice.
Therefore we use the set theoretic symbols $\cap$ and $\cup$ for meet and join.

One might expect the functions used to determine \textit{demands} and \textit{demanded by}
to be inverses of each other. It turns out this notion is not quite correct, for
two interlinked reasons. We do not consider individual values in the set of inputs
or outputs, and when selecting a set of inputs, we may select an input that is
entirely unused by the program.
If we were to insist our operations were inverse, it would imply that for a set of
inputs to be demanded by a set of outputs, every input in the set should be used,
which is clearly not always the case. We instead relax the requirement from the
two operations being inverse to their being, \textit{conjugate}, in the sense of \citet{jonsson51}:

\begin{definition}[Conjugate Functions]
   For Boolean algebras, $\powerset{X}$, and $\powerset{Y}$, functions $f: \powerset{X} \to \powerset{Y}$
   and $g: \powerset{Y} \to \powerset{X}$, and subsets $X' \subseteq X$ and $Y' \subseteq Y$,
   we say that $f$ and $g$ are \textit{conjugate} if the following holds:
   $$
      f(X') \cap Y' = \bot \iff X' \cap g(Y') = \bot 
   $$
\end{definition}

\begin{lemma}[Preimage and Image of a relation are conjugate]\label{lem:im-preim}
   For a relation $D \subseteq Y \times X$, and subsets $Y' \subseteq Y, X' \subseteq X$,
   $D[\param]$ and $\preim{D}[\param]$ are conjugate.
\end{lemma}

For convenience throughout this section, we make use of the fact that the
preimage of a relation $D$ is equal to the image of its converse. Thus,
alongside \lemref{im-preim}, we make use of the fact that the image 
of a relation is conjugate to the image of its converse.

The authors
of that paper provide the following alternate definition of conjugacy:

\begin{definition}[Computation of Conjugate Function]\label{def:construct-conjugate}
   Given a function $f: \powerset{X} \to \powerset{Y}$, there can exist only one
   conjugate function $g: \powerset{Y} \to \powerset{X}$. If $g$ exists we can
   calculate it using the following:
   $$
      g(Y') = \bigcap_{f(X') \cap Y' = \bot} \padArg{\compl{X}}{1em} \quad \text{for any $X' \in \powerset{X}$}
   $$
\end{definition}

In general, \defref{construct-conjugate} is inefficient, since it requires 
ranging over all possible values $a \in \mathcal{A}$, and computing their
meet with $b$.

\begin{definition}[Galois Connection For A Relation]
   For a relation $D \subseteq Y \times X$, we write $D_{\star} \dashv D^{\star} : \powerset{X} \to \powerset{Y}$
   to mean the image/preimage Galois connection for a function $f : X \to Y$, with the direction of the relation
   flipped, and the functions defined as:
   \begin{itemize}
      \item $D_{\star}(Y') \eqdef D[Y']$
      \item $D^{\star}(X') \eqdef \neg_{\powerset{Y}} \after D^{-1}[X'] \after \neg_{\powerset{X}} = \bigcup_{D^{-1}[Y'] \subseteq X'} \padArg{Y'}{0em} \quad (Y' \subseteq Y)$
   \end{itemize}
\end{definition}

\begin{definition}[Opposite Graph]
   For a graph $G = (V,E)$, define $G^{-1} \eqdef (V,E^{-1})$ to be the opposite graph,
   where $\param^{-1}$ denotes the relational inverse of an edge.
\end{definition}

\begin{definition}[Sources and sinks]
   Define:
   \begin{itemize}
      \item $\sources{G} \eqdef \set{\alpha \in \V(G) \mid \inN{G}(\alpha) = \emptyset}$ \hfill (sources)
      \item $\sinks{G} \eqdef \sources{G^{-1}}$ \hfill (sinks)
   \end{itemize}
\end{definition}


When a dependence graph $G$ is constructed, the sources $\sources{G}$ correspond
to the output nodes, and the sinks $\sinks{G}$ correspond to input nodes. In the
opposite graph, this correspondence is flipped.  

\begin{definition}[Reachability]
   For a graph $G=(V,E)$, the \textit{reachability relation} $R_G$ is the \textit{reflexive transitive
   closure} of $E$.
\end{definition}
We implicitly include edges of the form $e = (\alpha, \alpha)$ in the reachability
relation, since values like constants can be copied from the input directly through
to the output. In these cases, the node trivially depends on itself.

For the rest of this section we generally omit the $\param_G$
from this relation, since it is usually obvious to which graph we refer.
When we are considering a graph $G$ and it's opposite $G^{-1}$,
we will abuse the notation for the preimage and image of $R$,
since $R_G^{-1} = R_{G^{-1}}$. We can now define \textit{demands}
and \textit{demanded by} in terms of $R$.

\begin{definition}[Demands and Demanded By]
   For a graph $G = (V,E)$ with inputs $X \subseteq V$ and outputs $Y \subseteq V$, with reachability relation $R_G$, write the following:
   \begin{itemize}
      \item $\demandR_G \eqdef \restrict{R_G}{S(G) \times T(G)}[\param]$
      \item $\demandByR_G = \demandR_{G^{-1}}$
   \end{itemize}
\end{definition}

Let us return to the notion of a related input query. The first step is to select
the input of interest, $X' \subseteq \sinks{G}$. We proceed by finding all nodes
in the output that our selected input nodes are demanded by, $\demandByR(X')$.
We calculate this set by the algorithm detailed in \figref{conjugate:reaches}.

\begin{definition}[Related Inputs and Outputs]
   For $G = (V,E)$, define:
   \begin{enumerate}
      \item $\relInput_G \eqdef \demandR_G\cdot\demandByR_G$\hfill (related inputs)
      \item $\relOutput_G \eqdef \demandByR_G \cdot \demandR_G$\hfill (related outputs)
   \end{enumerate}
\end{definition}
