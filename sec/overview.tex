\subsection{Conjugate Operators over Dependence Graphs}
Here, we provide an informal view of our framework for bidirectional provenance queries over dependence graphs, which will be followed by a formal account in \secref{conjugate}.
As previosuly mentioned, our insight in this paper is that dependence graphs provide a language-agnostic foundation
for data transparency that both improves performance and reduces the implementation burden.

\edit{The operators  we use to perform
queries over a dependence graph form what's called a ``conjugate pair''. Conjugate pairs -- which map
between Boolean algebras -- have the property of maintaining ``overlap''. If the result of applying
one member of the pair to some subset of inputs $X' \subseteq X$ does not overlap with $Y' \subseteq Y$,
then applying the other member of the pair to $Y$ results in a set which does not overlap with $X'$.
This property intuitively holds of our dependency queries: if no member of a given input selection is demanded
by a given subset of the outputs, then that subset of outputs will not demand any memebr of the given inputs.}

The canonical example of conjugate operations are the image and preimage functions $\imageF{R}$ and
$\imageF{R^{-1}}$ for a relation $R \subseteq X \times Y$. It is not hard to see that if $\image{R^{-1}}{Y'}$
overlaps with $X'$ where $X' \subseteq X$ then necessarily $\image{R}{X'}$ overlaps with $Y'$ where $Y'
\subseteq Y$, and vice versa. Conjugate pairs are also closely related to Galois connections; if $f$ and $g$
are conjugate, then $f$ and the De Morgan dual of $g$ form a Galois connection (which will be explained in
more detail in \secref{conjugate}).

It is well-known that extensionally any one of these is enough to determine each other, but in the graph setting we

In the graph setting, the ``linked inputs'' and ``linked outputs'' relations can be computed by composing
reachability in $G$ with reachability in $\opGraph{G}$, which enables an efficient implementation. For example, linked outputs
can be written as $\demandsR_{R \relcomp R^{-1}}$, and linked inputs can be written as $\demandedByR_{R \relcomp R^{-1}}$.
In the graph, a pair of linked output values share some common ancestor whereas
a pair of linked input nodes in the graph share some common descendant. Therefore we will sometimes refer to linked outputs/inputs queries as computing ``peer'' values.

\subsection{\OurLang: A Data-Transparent Programming Language}

We implement the abstract framework outlined above in a programming language called \OurLang, a pure
functional language with a runtime implementing conjugate dependency operators. From the programmer's
perspective the language is unremarkable. The distinguishing feature of the language is a special
semantics that interprets a program not as a plain output but as an output with a built-in query engine
supporting the transparency features shown above. The author of a visualisation just expresses their chart as
a pure function of the inputs, via a set of data types for common visualisations; a d3.js front end
automatically enriches the rendered outputs with support for visual selection and various selection-based
queries.

In \secref{conjugate} we set out the formal graph framework and in \secref{core} show how the \OurLang
interpreter implements that abstract framework, we also provide some examples of the surface
language in \secref{core}, and some larger examples can be found in \apdxsecref{apdx:evaluation-src-code}.
Our implementation is open source and available at [anonymised], which also has several interactive demos.
