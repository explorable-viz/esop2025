\section{Overview: Fine-Grained Interactive Provenance}

There are four scenarios that constitute the interactive transparency features that we wish to automate; in
this section we describe these in some detail using figures generated by our implementation.
\figref{introduction:related-inputs} presents a data visualisation which investigates the efficiency of clean
energy usage, broken down geographically. The data is split across two tables providing information about
\textit{renewable} and \textit{non-renewable} energy sources; some of the data from the tables has been
summarised in the scatter plot on the right, where the x-axis represents the total renewables capacity over
total energy capacity, and the y-axis denotes the clean capacity factor computed as the total clean energy
output over the total clean energy capacity.

\paragraph{Fine-grained linking of the data to the view}
A user may also be interested in following the link between the input data and the output view. For instance,
the user may select China's bioenergy capacity (highlighted in green in~\figref{introduction:related-inputs},
row 205 in the data on the figure's left). Then, our system, through an operator we write as
$\demandedByR$, traces the data contained in this cell to the parts of the plot it was used to compute
(the green point in the plot). The bioenergy capacity contributes to both components of the point, namely the
total renewables capacity over total energy capacity and the clean capacity factor. We read $\demandedByR$
as computing ``what outputs is some input data \emph{demanded by}?''.

\paragraph{Linked inputs}
The previous use cases only went in one direction, either from outputs back to inputs, or from inputs to
outputs. However, there may be situations where we want to compose the two directions. For illustration, let's
assume like before that a user starts by selecting China's bioenergy capacity. As previously explained, our
system will apply $\demandedByR_{G}$ to trace the data contained in this cell to the point in the scatter plot
it was used to compute (the green point in the plot). Additionally \todo{under what circumstances? always?}, our
system will apply $\demandsR_{G}$ to determine the rest of the data in the input tables that was used to
compute the point in the plot (all data highlighted in grey in the tables). \todo{Probably unwise to use a
single figure with a single set of highlights to illustrate all three scenarios.} We refer to the highlighted
data \todo{green, grey or both?} in the two input tables as ``linked inputs'', i.e., inputs that contribute to
the same features of an output. This enables users to formulate queries like: “which outputs use this data
element, and which other data elements are used along with it?”.
