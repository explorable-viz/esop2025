\section{Overview: Fine-Grained Interactive Provenance}

In this section, we introduce the main interactive data provenance features that wish to provide, using two
\OurLang examples to illustrate. The line chart in \figref{introduction:related-inputs} shows projected
methane emissions from agricultural sources under a global warming scenario called RCP8.5; the scatter plot
and stacked bar chart in \figref{introduction:scatterplot} show non-renewable energy outputs and capacities
for various years and countries. The key idea of ``data transparent'' outputs is that the original data
sources are kept around and can be accessed (when a user so requests) from the output view, and the user is
then able to interact with both the data and the view to explore how they are related. Crucially the author of
the visualisations did not to have to implement these features themselves; they just expressed the charts in
question as pure functions of their inputs. The source code for the two examples are given in
\figrefTwo{example:moving-average:source}{example:non-renewables:source}.

\paragraph{1. Fine-grained linking of the data to the view.}

In \figref{introduction:related-inputs}, the user has chosen to reveal the underlying data set, which is shown
on the left; only rows relevant to the chart are shown, with the rest of the data hidden. This clarifies that
only agricultural data is relevant, confirming the (informal) claim in the caption. The emissions values shown
do contribute to the chart in some way, and the user can investigate this by interacting with individual
entries. For example, moving their mouse over the number 104.69 highlights \emph{one} point in the projected
emissions curve, and \emph{three} points in the other curve, which plots the moving average of the projected
emissions. The provenance analysis which underpins this we write as $\demandedByR$ (``demanded by''), and here
this tells us that that input value of interest is demanded by either the $x$ or $y$ coordinate (in this case
just the $y$) of the four highlighted points.

\paragraph{2. Fine-grained linking of the view back to the data.}

The user may want to query the input-output relationship the other direction too; for this we turn to
\figref{introduction:scatterplot}. Again the user has chosen to reveal the underlying data set, but this time
the user interface is only showing rows with active data selections, rather than rows with data that is used
somewhere in either of the charts. The provenance analysis at play here we write as $\demandedByR$ (``demanded
by'').

\paragraph{Linked inputs}

The previous use cases only went in one direction, either from outputs back to inputs, or from inputs to
outputs. However, there may be situations where we want to compose the two directions. For illustration, let's
assume like before that a user starts by selecting China's bioenergy capacity. As previously explained, our
system will apply $\demandedByR_{G}$ to trace the data contained in this cell to the point in the scatter plot
it was used to compute (the green point in the plot). Additionally \todo{under what circumstances? always?}, our
system will apply $\demandsR_{G}$ to determine the rest of the data in the input tables that was used to
compute the point in the plot (all data highlighted in grey in the tables). \todo{Probably unwise to use a
single figure with a single set of highlights to illustrate all three scenarios.} We refer to the highlighted
data \todo{green, grey or both?} in the two input tables as ``linked inputs'', i.e., inputs that contribute to
the same features of an output. This enables users to formulate queries like: “which outputs use this data
element, and which other data elements are used along with it?”.

\paragraph{Linked outputs}

Dually, we can start from an output, and want to determine all the “linked outputs”, i.e., outputs that
compete for the same input data. \todo{a.k.a.~linked brushing} One such scenario is illustrated in
\figref{introduction:scatterplot} where we have two output views: the same scatter plot as in
\figref{introduction:related-inputs}, and an additional bar chart denoting the non-renewables by country. In
the figure, the user has selected the segments corresponding to India in 2017, and Egypt and Japan in 2018 in
the bar chart. This highlights the corresponding data in the \textsf{nonRenewables} table used to produce
those outputs. Additionally, it also highlights any outputs in the scatter plot that demand any of those data.
The selected bars in the bar chart and the selected points (specifically, their x-ccordinates as those are the
ones using the considered input data) in the scatter plot are the linked outputs. In the scatter plot, we note
that only two points are selected, those for Egypt and Japan, reflecting the fact that the scatter plot is
only a view of data from 2018.

selected segment of the bar, with each set of coloured segments associated with a given nation -- the selected
segments demand all of the highlighted green data in the table. Then, starting from the selected data, we
apply $\demandedByR_{G}$ to pick out the $x$ components of some of the circles in the scatter plot (green
circles). \todo{Last two paragraphs verbose}
