\subsection{Syntax and graph terms}

\input{fig/core/syntax}

\begin{definition}[Finite map notation]\label{def:finite-map}
   Write $\set{\seq{\bind{k}{v}}}$ to denote a set of pairs $\seqRange{\bind{k_1}{v_1}}{\bind{k_n}{v_n}}$
   where $\seqRange{k_1}{k_n}$ are pairwise unique.
\end{definition}

\figref{syntax} defines the graph terms $e$ of the language as regular terms $\raw{e}$ indexed by an ``address'' $\alpha$. An address is a unique identifier for a term as a node in the graph; the other main language constructs that we introduce later, which are eliminators, values, and patterns, also correspond to graph nodes. Regular terms $\raw{e}$ include integers ranged over by $n, m$, variables ranged over by $x, y, f$, let-bindings $\exLet{x}{e}{e'}$%
, record construction $\exRec{\seq{\bind{x}{e}}}$ (see \defref{finite-map})% which maps variables to terms (\defref{finite-map})
, record projection $\exRecProj{e}{x}$% for accessing variable $x$ in record $e$
, and data values $\exConstr{c}{\seq{e}}$ where $c$ ranges over data constructors and is fully saturated by arguments $\seq{e}$. As well as regular application $\exApp{e}{e'}$, we also have  \emph{foreign application} $\exForeignApp{f}{\seq{e}}$. The last two terms define anonymous functions $\exFun{\sigma}$ and recursive let-bindings $\exLetRecElim{\seq{x : \sigma}}{e}$ where $\sigma$ is a pattern-matching construct called an \emph{eliminator}. We introduce eliminators in \secref{core:continuations} and foreign functions in \secref{core:foreign}.

\subsubsection{Continuations and eliminators}
\label{sec:core:continuations}
\input{fig/core/match}
A \emph{continuation} $\kappa$ is either a term $e$ or an \textit{eliminator} $\sigma$. Eliminators are trie-like objects
which can serve as a plausible desugaring target for surface-language pattern-matching constructs.
(\citet{peytonjones2021} present a similar idea in a technical report.)


\subsubsection{Foreign functions}
\label{sec:core:foreign}
The language is parameterised by a finite map $\Phi: \Var \to \Type^+ \times \Type$ from variables to foreign
function signatures $(\seq{A}, B)$. By convention $f$ and $\oplus$ ranges over $\dom{\Phi}$. Foreign functions
\emph{per se} are not first-class and calls $\exForeignApp{f}{\seq{e}}$ are saturated, i.e.~$\length{\seq{e}}
= \length{\seq{A}}$. First-class foreign functions are provided via a top-level environment which maps every
$\bind{f}{(\seq{A}, B)} \in \Phi$ to the closure
$\exClosure{\seqEmpty}{\seqEmpty}{\elimVar{x_1}{\elimVar{\iter}{\elimVar{x_i}{\exForeignApp{f}{\seq{x}}}}}}$
where $\length{\seq{x}} = \length{\seq{A}}$. Although saturated calls are technically part of the languageœ, user programs by convention use the first-class representation.
