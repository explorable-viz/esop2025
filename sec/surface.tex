\section{Surface Language}
\label{sec:surfacesemantics}
When presenting a program execution, we want to give the appearence to the user that they are executing parts
of the surface language directly. To that end we formalise and present a notion of evaluation of surface
terms, which we present to the user in the debugger. We most formalise a notion of values in the surface
language, which mostly correspond to values in the core language. We then present proof that directly
evaluating a surface program produces the same result as desugaring it to a core program and evaluating that.
This correspondence justifies our presentation of the surface semantics to the debugger.

\subsection{Compatible Patterns}
One complication of defining semantics for the surface language is how to deal with functions defined
equationally. In particular, functions defined with equations are subject to conditions on how they perform
pattern matching. We need to define a notion of pattern matching for surface terms, that roughly corresponds
to pattern matching in the core language. This is made more complicated by the lack of eliminators in the
surface language. We therefore need to define a notion of compatible patterns for defining functions
equationally, and a notion of pattern matching for surface values.

\subsection{Desugaring Of Values, Environments and RecDefs}
In order to state the theorem, we must extend our definition of desugaring to values. For values, we only have
one interesting case, that of surface closures. To define the desugaring of surface-closures, we need to define

\subsection{Equivalence of Semantics}
Informally, the equivalence of the semantics means that if we take a surface term, and an environment, we can 
either desugar the term, and then evaluate it, or we can evaluate it, and then desugar the result. We need this
theorem, as it is our intent that the user is presented with the surface semantics, even though we execute the
program using the core semantics. Without this theorem, we could not properly justify this choice, as fluid has
some non-trivial desugaring. We formalise the equivalence of these semantics as the following theorem.
\begin{theorem}
    Suppose $\Gamma \vdash s : A \; and \; \upgamma : \Gamma$, then:
\hfill
\begin{enumerate}
    \item $ If \; \upgamma, s \evalSugS v \; then \; \exists \upgamma', e.\; s \desugarFwdS e \; and \; \upgamma \desugarFwdS \upgamma' \; and \; \upgamma', e \evalFwdS v' \; where \; v \desugarFwdS v'$
    \item $If \; \upgamma \desugarFwdS \upgamma' \; and \; s \desugarFwdS e \; and \; \upgamma',e \evalFwdS v \; then \; \exists v'. \; \upgamma, s \evalSugS v' \; where \; v' \desugarFwdS v$
\end{enumerate}
\end{theorem}
The sketch of the proof is as follows: for many cases of evaluation, the rules for surface and core evaluation are 
matched exactly. For these rules, provided the desugaring relations are defined correctly, we can probably 
call those proof cases trivial. There are a number of more interesting cases, specifically the ones to do with 
list comprehensions and function applications. Since we have slightly changed the semantics of functions (FFI etc)
this should be a bit easier. We can likely inline most definitions.
