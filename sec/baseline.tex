\section{Baseline language (without graphs)}
\label{sec:baseline}
\subsection{Surface Language}

When presenting a program execution, we want to give the appearence to the user that they are executing parts
of the surface language directly. To that end we formalise and present a notion of evaluation of surface
terms, which we present to the user in the debugger. We most formalise a notion of values in the surface
language, which mostly correspond to values in the core language. We then present proof that directly
evaluating a surface program produces the same result as desugaring it to a core program and then evaluating, justifying our presentation of the surface semantics to the debugger.

\subsubsection{Desugaring Of Values, Environments and Recursive Definitions}

In order to state the theorem, we must extend our definition of desugaring to values. For values, we only have
one interesting case, that of surface closures. To define the desugaring of surface-closures, we need to define
desugaring for environments, and recursively-defined functions (in surface language $\seq{g}$, in core $\uprho$).
Once this extension to the desugaring relation has been carefully defined, in figure \ref{fig:closures}, we can state and prove our theorem.

\subsubsection{Equivalence of Semantics}

Informally, the equivalence of the semantics means that desugaring a surface term and surface environment
produces the same result as surface-evaluating to a surface value and then desugaring the surface value.
We formalise the equivalence of these semantics as the following
theorem.
\begin{theorem}
   \label{thm:semantics-eq}
   Suppose $\upGamma \vdash s : A, \; \upgamma : \upGamma, \; s \desugarFwdS e, \; and \; \upgamma \desugarFwdS \upgamma'$, then:
\hfill
\begin{enumerate}
   \item $ If \; \upgamma, s \evalSugS v \; then \; \upgamma', e \evalFwdS v' \; where \; v \desugarFwdS v'$ \label{thm:semantics-eq-1}
   \item $If \; \upgamma',e \evalFwdS v' \; then \; \upgamma, s \evalSugS v \; where \; v \desugarFwdS v'$   \label{thm:semantics-eq-2}
\end{enumerate}
\end{theorem}
\begin{proof}
   For \thmref{semantics-eq}.1 see \appref{semantics-eq-1}, and for \thmref{semantics-eq}.2, see \appref{semantics-eq-2}
\end{proof}
\thmref{semantics-eq} relies on pattern-matching in the surface and core languages producing
environments that coincide sensibly. We state this as \lemref{matching-bi}. We need to
also establish that environment lookup commutes with desugaring, \lemref{lemma:varlookup}. Due to the fact
that desugaring of values is not a total relation, we require that both $s$ and $\upgamma$ can be desugared as
the precondition to \thmref{semantics-eq}. We also need to establish that closing
a set of definitions behaves the way we want it to, in \lemref{closedefs-eq}. We also need to establish some 
properties on recursively defined functions and the eliminators they desugar to so that we can characterize 
their surface evaluation properly, which we do in \lemref{disjoint-clause-elim}.
\begin{lemma}
   \label{lem:lemma:varlookup}
   Suppose we have $\upgamma \desugarFwdS \upgamma'$ and $v \desugarFwdS v'$, then
   $$
      \bind{x}{v} \in \upgamma \quad \iff \quad \bind{x}{v'} \in \upgamma'
   $$
\end{lemma}
\begin{proof}
   See \appref{proofs:varlookup}
\end{proof}
\begin{lemma}
   \label{lem:matching-bi}
   Suppose we have $v \desugarFwdS v'$, and $\upmu$, Then:
   \hfill
   \begin{enumerate}
      \item If $v, \upmu\matchFwdS \upgamma, s$ and $\upmu \desugarFwdS \upsigma$ then $v',\upsigma \matchFwdS \upgamma', e$ with $\upgamma \desugarFwdS \upgamma'$ and $s \desugarFwdS e$
      \item If $\upmu \desugarFwdS \upsigma$ and $v', \upsigma \matchFwdS \upgamma', e$ then $v, \upmu \matchFwdS \upgamma, s$ and $\upgamma \desugarFwdS \upgamma'$ and $s \desugarFwdS e$
   \end{enumerate}
   
\end{lemma}
\begin{proof}
   As in \thmref{semantics-eq}, we split the proof into 2 parts, for \lemref{matching-bi}.1 see \appref{proofs:matching-bi-1} and for \lemref{matching-bi}.2, see \appref{proofs:matching-bi-2}.
\end{proof}
\begin{lemma}
   \label{lem:closedefs-eq}
   Suppose we have $\upgamma_1 \desugarFwdS \upgamma_2$, and $g \desugarFwdS \uprho$. Then
   \hfill
   \begin{enumerate}
      \item If $\upgamma_1, g \closeDefsS \upgamma_1'$ then $\upgamma_2, \uprho \closeDefsS \upgamma_2'$ where $\upgamma_1' \desugarFwdS \upgamma_2'$
      \item If $\upgamma_2, \uprho \closeDefsS \upgamma_2'$, then $\upgamma_1, g, \closeDefsS \upgamma_1'$ where $\upgamma_1' \desugarFwdS \upgamma_2'$
   \end{enumerate}
\end{lemma}
\begin{proof}
   see \appref{proofs:close-defs-eq}
\end{proof}

\subsection{Desugaring}
The most interesting cases of desugaring in our language are those relating to sequences of clauses. Ensuring pattern matching is 
consistent in both the core and surface languages is imperative for \thmref{semantics-eq}. We disallow certain combinations of 
patterns which might otherwise be allowed in another language. For example, we do not allow clauses formed in the following fashion:
{\small
\begin{lstlisting}[language=Fluid]
   foo (Cons y ys) (Cons z zs) = ...
   foo  x           Nil        = ...

   bar x ... = ...
   bar y ... = ...
\end{lstlisting}}
In other words, when we have variable patterns, the appropriately indexed arguments must all be variable patterns with the same name,
and when we have a position where we have a variable pattern and a constructor, we must have already been able to distinguish 
both arguments. As pattern matching proceeds from left to right, this means that the following \textit{is} allowed:
{\small
\begin{lstlisting}[language = Fluid]
   baz :: forall a b. List a -> List a -> b
   baz (Cons y ys) (Cons z zs) = ...
   baz  Nil         x          = ...
\end{lstlisting}}
