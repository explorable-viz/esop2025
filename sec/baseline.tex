\section{Baseline language (without graphs)}
\label{sec:baseline}
\subsection{Surface Language}

When presenting a program execution, we want to give the appearence to the user that they are executing parts
of the surface language directly. To that end we formalise and present a notion of evaluation of surface
terms, which we present to the user in the debugger. We most formalise a notion of values in the surface
language, which mostly correspond to values in the core language. We then present proof that directly
evaluating a surface program produces the same result as desugaring it to a core program and then evaluating, justifying our presentation of the surface semantics to the debugger.

\subsubsection{Mutual recursion}

\figref{close-defs-surface} defines the relation $\closeDefsS$ which creates the environments associated with
a block of mutually recursively defined functions. Given an environment $\gamma$ and a sequence of recursively
defined functions $g = \seq{\bind{x}{\mu}}$ (read $x$ as the function name and $\mu$ as the clauses of the
function), we split the sequence into each individual function $\bind{x}{\mu}$ and form the closure
associated with the function.

\subsubsection{Desugaring Of Values, Environments and Recursive Definitions}

In order to state the theorem, we must extend our definition of desugaring to values. For values, we only have
one interesting case, that of surface closures. To define the desugaring of surface-closures, we need to define
desugaring for environments, and recursively-defined functions (in surface language $\seq{g}$, in core $\rho$).
Once this extension to the desugaring relation has been carefully defined, in figure \figref{closures}, we can state and prove our theorem.

\subsubsection{Equivalence of Semantics}

Informally, the equivalence of the semantics means that desugaring a surface term and surface environment
produces the same result as surface-evaluating to a surface value and then desugaring the surface value.
We formalise the equivalence of these semantics as the following
theorem.
%  $\Gamma \vdash s : A, \; \gamma : \Gamma,
\begin{theorem}
   \label{thm:semantics-eq}
   Suppose $s \desugarFwdS e \; and \; \gamma \desugarFwdS \gamma'$, then:
\hfill
\begin{enumerate}
   \item $ If \; \gamma, s \evalSugS v \; then \; \gamma', e \evalFwdS v' \; where \; v \desugarFwdS v'$ \label{semantics-eq-1}
   \item $If \; \gamma',e \evalFwdS v' \; then \; \gamma, s \evalSugS v \; where \; v \desugarFwdS v'$   \label{semantics-eq-2}
\end{enumerate}
\end{theorem}
\begin{proof}
   For (1) see \appref{semantics-eq-1}, and for (2), see \appref{semantics-eq-2}
\end{proof}
\thmref{semantics-eq} relies on pattern-matching in the surface and core languages producing
environments that coincide sensibly. We state this as \lemref{matching-bi}. We need to
also establish that environment lookup commutes with desugaring, \lemref{lemma:varlookup}. Due to the fact
that desugaring of values is not a total relation, we require that both $s$ and $\gamma$ can be desugared as
the precondition to \thmref{semantics-eq}. We also need to establish that closing
a set of definitions behaves the way we want it to, in \lemref{closedefs-eq}. We also need to establish some
properties on recursively defined functions and the eliminators they desugar to so that we can characterize
their surface evaluation properly, which we do in \lemref{disjoint-clause-elim}.
\begin{lemma}
   \label{lem:lemma:varlookup}
   Suppose $\gamma \desugarFwdS \gamma'$ and $v \desugarFwdS v'$, then
   $$
      \bind{x}{v} \in \gamma \quad \iff \quad \bind{x}{v'} \in \gamma'
   $$
\end{lemma}
\begin{proof}
   See \appref{proofs:varlookup}
\end{proof}
\begin{lemma}
   \label{lem:matching-bi}
   Suppose $v \desugarFwdS v'$ and $\mu \desugarFwdS \sigma$, Then:
   \hfill
   \begin{enumerate}
      \item If $u, \mu\matchFwdS \gamma, s$ then $\exists \gamma', e.v,\sigma \matchFwdS \gamma', e$ with $\gamma \desugarFwdS \gamma'$ and $s \desugarFwdS e$
      \item If $v, \sigma \matchFwdS \gamma', e$ then $u, \mu \matchFwdS \gamma, s$ and $\gamma \desugarFwdS \gamma'$ and $s \desugarFwdS e$
   \end{enumerate}

\end{lemma}
\begin{proof}
   As in \thmref{semantics-eq}, we split the proof into 2 parts, for (1) see \appref{proofs:matching-bi-1} and for (2), see \appref{proofs:matching-bi-2}.
\end{proof}
\begin{lemma}
   \label{lem:closedefs-eq}
   Suppose $\gamma_1 \desugarFwdS \gamma_2$ and $g \desugarFwdS \rho$. Then
   \hfill
   \begin{enumerate}
      \item If $\gamma_1, g \closeDefsS \gamma_1'$ then $\gamma_2, \rho \closeDefsS \gamma_2'$ where $\gamma_1' \desugarFwdS \gamma_2'$
      \item If $\gamma_2, \rho \closeDefsS \gamma_2'$, then $\gamma_1, g, \closeDefsS \gamma_1'$ where $\gamma_1' \desugarFwdS \gamma_2'$
   \end{enumerate}
\end{lemma}
\begin{proof}
   see \appref{proofs:close-defs-eq}
\end{proof}

Proving \lemref{disjoint-clause-elim} is quite challenging, but is a requirement for the proof of \thmref{semantics-eq}.
Our current intuition is that we need to prove some properties about eliminators in order to make this tractable.
We shall break these down.
\subsubsection{Vertical Recursion}
For now, we are using the term "vertical recursion" to mean the case of desugaring a sequence of clauses.
The definition of this, at the top of \figref{desugar-func-qual-do} ($\desugarFwdS$-clauses)
demonstrates the need to join the eliminator formed by desugaring the previous equations with the
next clause in the definition. We need this join operation ($\disjjoin$) to always be defined
for well-typed definitions of a recursive function. We have captured this intuition with the maxim
"disjoint join preserves joinability". We will make this notion more formal in a revision of this draft.
\subsubsection{Horizontal Recursion}
The other part that makes this difficult is the notion of curried patterns. An eliminator is
a branching structure as we have noted. However an individual clause is sequential with no branching.
The branching is introduced when we consider multiple clauses for the same function. We need the proof
of the lemma to be constructive, to show exactly how we compute the join when it is defined.
Our intuition is that the only point in an eliminator where we encounter branching
is at the point of disjoint constructors, however this branch may be nested deeply inside other
constructor and record patterns. We think we need to revise our definition of eliminators
in order to make this intuition clear and easy to prove, as our current approach to proving
\lemref{disjoint-clause-elim} relies on this unproven fact.

\subsection{Desugaring}
The most interesting cases of desugaring in our language are those relating to sequences of clauses. Ensuring pattern matching is
consistent in both the core and surface languages is imperative for \thmref{semantics-eq}. We disallow certain combinations of
patterns which might otherwise be allowed in another language. For example, we do not allow clauses formed in the following fashion:
{\small
\begin{lstlisting}[language=Fluid]
   foo (Cons y ys) (Cons z zs) = ...
   foo  x           Nil        = ...

   bar x ... = ...
   bar y ... = ...
\end{lstlisting}}
In other words, when we have variable patterns, the appropriately indexed arguments must all be variable patterns with the same name,
and when we have a position where we have a variable pattern and a constructor, we must have already been able to distinguish
both arguments. This does not mean that the rest of the function can be ill-typed. Just because we have distinguished
the two clauses in the following example, we still cannot consider it a well-formed program.
{\small
\begin{lstlisting}[language = Fluid]
   baz (Cons y ys) (Cons z zs) = ...
   baz  Nil         x          = ...
\end{lstlisting}}
